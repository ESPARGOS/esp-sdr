Original ESP32 and S31 UART hardware follow-up — 2026-10-08

This extends dc-retune-all.txt with the newly accessible original ESP32 and
repeat S31 UART validation. S31 native USB/Soapy streaming is NOT validated:
its production streaming image booted and enumerated, but the OS denied USB
access. At the user's request, testing switched to the regular UART profile.
The final S31 installation is that regular profile, not the Soapy profile.

Boards

Original ESP32: ESP32-D0WD-V3 rev. 3.1, MAC f4:65:0b:b5:65:8c,
40 MHz crystal, CP2102N on /dev/ttyUSB3. A 2 MiB flash backup was saved first.
S31: MAC 30:ed:a0:f3:f8:40, CP2102N on /dev/ttyUSB1; same board as the earlier
S31 burst tests. UART used 2 Mbaud for ESP32 and 1 Mbaud for S31.

Bug found and repaired

The original ESP32 correctly noticed changed PHY DC tables, but CAP20 did not
call prepare_rx(), leaving calibration stale after the capture. The original
hardware recovery test failed this assertion. acquire_iq() now checks for
stale calibration and prepares reception before starting acquisition. This
common entry point covers raw captures, RXRUN and snapshot spectra. Fresh
captures avoid extra receiver reconfiguration; invalid capture arguments are
still rejected before touching hardware.

The new host regression test simulates acquisition registers and asserts that
stale state is repaired before any capture register write. It exercises raw
and spectrum acquisition, repeated fresh captures, and argument rejection.
It fails against the previous committed source and passes with the repair.
All 54 host tests pass. This is a correction to the earlier compile-only
qualification of the original ESP32, not merely additional test coverage.

Recovery and UART spectrum results

Each board passed 20/20 real reference-DC overwrite trials: five each at
2350, 2370, 2413 and 2484 MHz. The test invokes the actual DC calibration at
2412 MHz without changing the requested frequency or cached application
state. The next capture must change stale -> fresh without another FREQ
command, pass CRC, and preserve manual gain. These are forced measurements,
not controlled physical temperature cycling.

Original ESP32 maximum immediate post-recovery DC magnitude was 69.3 ADC
counts at gain 45. Most captures were much lower; some 2413 MHz captures had
up to 3% clipping in the nearby-antenna environment. S31 maximum was 24.2
counts with no clipped samples. These limits are recorded rather than claiming
all frequencies/gains now have small DC offsets.

Both also passed four 1.5-second UART spectrum runs, one at each frequency,
with another reference-DC overwrite immediately before each run. At 1024 FFT
bins / 80 MS/s, ESP32 delivered 768 and S31 572 CRC-valid spectrum frames.
Sequence numbers and sample positions were checked, each run ended normally,
calibration became fresh, and manual gain 40 was preserved. UART spectra are
snapshots with acquisition gaps; these tests do not establish gapless IQ.

HackRF results

Same nearby-antenna method as the earlier report, alternating 2350/2351 MHz
with 40 commands and 39 actual changes. Detection inspects the LO+5 MHz tone
with an idle-99th-percentile +12 dB threshold. Event windows allow 10 ms before
the command and 30 ms after its response for host USB timestamp uncertainty.

Original ESP32 baseline: 39/39 detected, peak -42.0 dBFS.
Original ESP32 repaired: 0/39 detected, peak -68.2 dBFS.
S31 regular fixed firmware: 0/39 detected, peak -68.1 dBFS.
This confirms the original ESP32 emission improvement; S31's positive baseline
comparison was already recorded in dc-retune-all.txt.

Both received bounded HackRF tones at 2352 and 2372 MHz with LO at 2350 and
2370 MHz. Minimum tone SNR / image rejection across eight recorded captures:
Original ESP32 baseline: 19.5 / 11.0 dB.
Original ESP32 repaired: 15.5 / 11.7 dB.
S31 fixed: 40.4 / 35.0 dB.
This proves reception in this setup, not equal sensitivity or image rejection
across firmware, boot calibrations, frequencies or temperatures. ESP32 reception
was weaker than on S31; antenna coupling and gain were not calibrated.

Evidence and final installation

Local evidence is in artifacts/dc-followup/: backup, build/flash logs,
regression-before-fix.log, host-tests.log, recovery JSON, CRC spectrum results,
HackRF NPZ/JSON, test scripts and diagnostic source. Earlier ESP32 baseline
and first diagnostic leakage/DC data are in artifacts/dc-retune-all/.
final-verification.json records production images, installed revisions and
post-installation captures. The original ESP32 and S31 are left running the
regular production firmware; no diagnostic commands remain installed.

Only ESP32's acquisition path changes in this follow-up. S31 uses the existing
committed calibration implementation. All other hardware qualifications and
limitations in dc-retune-all.txt still apply, including the absence of S31
native USB/Ethernet streaming validation and S2 antenna testing.
